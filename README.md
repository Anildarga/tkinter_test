# SampleApp signed updates

SampleApp demonstrates a Windows per-user installer and signed, whole-folder
updates. The private signing key is generated by you and must never be included
in this repository, an app bundle, or a GitHub Release.

## One-time setup

1. Create a virtual environment and install the pinned build dependencies:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Generate an encrypted Ed25519 private key outside the project. The script
   writes the matching public key into `update_public_key.py`:

   ```powershell
   .\.venv\Scripts\python.exe .\generate_signing_key.py `
     --private-key "$env:USERPROFILE\sampleapp-signing-key.pem"
   ```

   Choose a strong passphrase and keep both the key file and passphrase backed
   up securely. Do not upload the private key. Add the public-key change to
   source control so installed apps can verify releases.

3. For GitHub Actions publishing, add repository secrets:
   - `UPDATE_SIGNING_KEY_B64`: base64 of the encrypted private PEM. PowerShell
     can produce it with:

     ```powershell
     [Convert]::ToBase64String(
       [IO.File]::ReadAllBytes("$env:USERPROFILE\sampleapp-signing-key.pem")
     )
     ```

   - `UPDATE_SIGNING_PASSPHRASE`: the PEM passphrase.

   Also configure GitHub Pages to use **GitHub Actions** as its source. The
   release workflow deploys the signed manifest to
   `https://anildarga.github.io/tkinter_test/latest.json`.

## Build and install locally

Set `APP_VERSION` in `main.py` and `AppVersion` in `SampleApp.iss` to the same
release version. Then run:

```powershell
.\build.ps1 -ReleaseVersion 1.1.0
```

The one-folder bundle is `dist-modern\SampleApp`. Compile `SampleApp.iss` with
Inno Setup to produce a per-user installer under `installer-output`. The
installer targets `%LOCALAPPDATA%\Programs\SampleApp`; both `SampleApp.exe`
and `Updater.exe` must stay together in that folder.

## Publish a release

Push a version tag matching `APP_VERSION`, for example `v1.1.0`. The GitHub
Actions workflow checks out the tag, builds the onedir app and updater, zips
the complete app folder, hashes it, signs `latest.json`, publishes the ZIP and
manifest as release assets, and deploys the manifest to GitHub Pages.

The app downloads the signed manifest from Pages rather than using the
rate-limited GitHub Releases API. The manifest includes the version, HTTPS
package URL, SHA-256, release notes, and minimum supported app version. Its
Ed25519 signature covers every manifest field other than `signature`.

## Update behavior and trust

The app checks automatically no more than once per 24 hours and also provides
a manual **Check for updates** button. It verifies the manifest signature
before trusting its fields, downloads the ZIP, verifies its SHA-256, and starts
a temporary copy of the updater. The updater waits for the app to exit, checks
the archive hash again, safely extracts into a staging folder, swaps the
folders, launches the new app, and rolls back if startup fails. It retains the
latest successful backup and removes older backups after the new version
starts.

The checksum is useful for detecting corruption; the Ed25519 signature
authenticates the manifest against the public key embedded in the app. If the
private signing key is lost or compromised, updates signed by the replacement
key will not be accepted until users receive an app containing its new public
key. Treat the private key and passphrase as production credentials.
